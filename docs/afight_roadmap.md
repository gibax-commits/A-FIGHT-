## 1. 土台となる3機能

以下の3つは**他の多くの機能がこれに乗る**ため、先に固めておく必要がある。
逆に言えば、ここが決まらないと上物の設計が確定しない。

### 1-A. セーブスロット(TYPE別)

**現状の問題**:セーブデータが1つしか無く、他のTYPEで始めるには既存データを潰すしかない。
ロードボタンも無いため、そもそも任意のタイミングでロードができない。

- TYPE別(A/B/C)にスロットを分ける
- ロードボタンの追加
- タイトルに戻るボタンの追加(現在タイトルへ戻る手段が無い)

**これが前提になるもの**:オープニング、TYPE選択画面、起動シークエンス、名付け
(いずれも「新しく1体を迎える」流れなので、複数スロットが無いと体験として成立しない)

### 1-B. シンクロ率のブラッシュアップ

**現状の問題**:テストプレイ用に新規開始時から150%固定になっている。
本来は起動シークエンスで初期値が決まり、以降メンテナンスで増減する数値。

- 初期値の決定(起動シークエンスの結果に応じて変動)
- 増減のルール(戦闘での消耗、メンテナンスでの回復)
- 上限の概念(育成で引き上げ)

**これが前提になるもの**:メンテナンスゲージ、メンテナンスモード、育成(最大値引き上げ)、起動シークエンス

### 1-C. ペーパードール本実装

**現状の問題**:装備しても見た目に反映されない(サンプルソードのみ例外的に手に描画)。

- 型(シルエット)画像+動的着色+オーバーサイズ描画
- ユニークエフェクトの視覚的な描画
- 装備カテゴリーごとの重ね順・アンカー定義

**これが前提になるもの**:髪型変更(見た目に反映されないと意味が無い)

## 2. 導入・世界観(一連の流れ)

**1-A(セーブスロット)が前提**。以下は「新しいパートナーを迎える」までの一続きの体験として設計する。

```
タイトル画面
  ↓
オープニング(テキストで世界観を語る)
  ↓
TYPE選択画面(カタログを眺めて購入機体を決める)
  ↓
起動シークエンス(自宅に届いた機体を起動する / シンクロ率初期値が決まる)
  ↓
名付け
  ↓
ROOM(以降が既存のゲーム本編)
```

### 2-A. タイトル画面

現状は簡易的な画面。世界観を印象づける入口として作り直す。

### 2-B. オープニング(テキスト)

A-FIGHTの世界観を語る導入。テキスト送り形式。

### 2-C. TYPE選択画面

**「主人公がカタログを眺めて、購入する女性型アンドロイドを決める」**という描写。

- 1画面につき1体、**サイドスワイプでA→B→Cを切り替える**カタログ風UI
- 各TYPEの立ち絵を大きく表示(実装済みの立ち絵を流用可)
- カタログとしての説明文(スペック・性格傾向)

### 2-D. 起動シークエンス

購入した機体が自宅に届き、初めて起動する場面。**シンクロ率の初期値がここで決まる。**

**直感的操作による三択**:

| 操作 | 内容 |
|---|---|
| タップ | 触れる |
| スワイプ | 撫でる |
| ホールド(長押し) | 手を添える |

**TYPEごとに「正解」が異なる**(性格設定と対応):

| TYPE | 性格 | 正解の操作 |
|---|---|---|
| TYPE-A | 冷静・生真面目 | 頭を**ホールド**(手を添える) |
| TYPE-B | 純真・従順 | 頭を**スワイプ**(撫でる) |
| TYPE-C | 勝気・ツンデレ | 頭を**タップ**(触る) |

- 正解/不正解で**シンクロ率上昇が大・中・小**に分岐
- それぞれに**TYPE別の反応テキストと表情**を用意
- 会話表示は**画面下部のパネルを切り替える方式**(ARENAの ENEMY DATA と同じ仕組みを流用)
- 立ち絵は**バストアップに切り替えて表情を見せる**(ADVゲーム方式)
- 起動前の演出として**目閉じの全身立ち絵**も使用する
- **この仕組みはメンテナンスモードにも応用する**(素材・実装ともに共用できる)

### 2-E. 名付け

パートナーとなるアンドロイドに名前を付ける。以降ゲーム内で使用される。

## 3. ストーリーとチュートリアル

### 3-A. ストーリーモード(新モード)

本編のストーリー。**会話ウインドウ**(戦闘中の全体ログ欄を転用する想定)でテキストを表示する。

### 3-B. チュートリアル

**ストーリーモードと絡めた形**で実装する。単独のチュートリアル画面ではなく、
物語の流れの中で操作を覚えていく設計。

> 現在はテストプレイ前提のため説明が一切無い状態。新規プレイヤーには
> AP・射程・地形・アーキタイプなど覚えることが多いため、段階的な導入が要る。

## 4. シンクロ率とメンテナンス

**1-B(シンクロ率のブラッシュアップ)が前提。**

### 4-A. メンテナンスゲージ

シンクロ率の増減に絡むゲージ。戦闘で消耗し、メンテナンスで回復する想定。

### 4-B. メンテナンスモード(新モード)

シンクロ率を回復・維持するためのモード。
**起動シークエンスと同じ直感的操作(タップ/スワイプ/ホールド)を応用する。**

- TYPEごとの正解操作、反応テキストの仕組みを共用できる
- 素材(立ち絵の表情差分、目閉じ全身など)も共用できる
- **メンテナンスする部位/範囲の選択**という要素を持つ
  - 選択を誤ると**羞恥**の反応となり、シンクロ率が若干減少する
  - さらに踏み込んだ失敗は**苦痛**の反応となり、減少幅が大きくなる
- 単なる回復作業ではなく、**正しく接することを探る**駆け引きにする

## 5. 育成・カスタマイズ

### 5-A. 育成要素

- **シンクロ率の最大値引き上げ**
- **装備強化**

現状は「より良い装備を引く」以外に強くなる手段が無いため、
継続プレイの動機付けとして機能させたい。

### 5-B. 髪型変更

- CLOSETに**新カテゴリー**として追加
- 入手は**マテリアルを消費して解放**する方式
- 各種装備と同様に**ペーパードールで見た目に反映**(1-Cが前提)

**前髪+サイド / 後ろ髪を別々に選べる方式**にする:

```
[前髪+サイド]   ← 体より手前に描画
[髪無しベース]  ← 顔・耳・首・肩まで描いたもの
[後ろ髪]        ← 体より奥に描画
```

- 別枠で解放できるため、**組み合わせでバリエーションが掛け算で増える**
  (後ろ髪ツインテール × 前髪パターンA/B/C など)
- 髪型1種の追加コストが小さく済む(素材リスト 2-3節)
- **戦闘中の反映は当面見送り**(最小90pxまで縮小され差が見えにくいため)

## 7. 構想のみ(優先度低)

### 7-A. 対戦モード

**現時点では優先度を低く見ている。** 理由:

- ストーリー/メンテナンス/育成と、既に大きなモードが3つ控えている
- 対戦は「相手をどう用意するか」が本質的に難しい
- 現在のARENAが実質的に対戦の役割を果たしており、防衛戦・オーパで上位帯の張り合いも成立している

もし実装するなら、**育成が実装された後に「他プレイヤーのセーブデータを模した仮想対戦相手」**という形が現実的。

## 8. 依存関係まとめ

```
[1-A セーブスロット] ──┬─→ 2-A タイトル画面
                        ├─→ 2-B オープニング
                        ├─→ 2-C TYPE選択画面
                        ├─→ 2-D 起動シークエンス
                        └─→ 2-E 名付け

[1-B シンクロ率]     ──┬─→ 2-D 起動シークエンス(初期値決定)
                        ├─→ 4-A メンテナンスゲージ
                        ├─→ 4-B メンテナンスモード
                        └─→ 5-A 育成(最大値引き上げ)

[1-C ペーパードール] ──┬─→ 5-B 髪型変更
                        └─→ (ユニークエフェクトの視覚化)

[3-A ストーリーモード] ─→ 3-B チュートリアル

[2-D 起動シークエンス] ←→ [4-B メンテナンスモード]  ※直感的操作の仕組みを共用
```

**独立して進められるもの**:6-A(tips)、2-A(タイトル画面の見た目のみ)
